# AGENTS.md

Guidance for agents working in this repository.

## Project overview

**keywoo** is a small URL opener web app built with Flask. Users sign up, log in, and
save named URLs; the app renders a result page that opens the saved links.

- Production site: <https://keywoo.yumenomatayume.net>
- License: MIT

## Setup

Dependencies and the Python interpreter are managed by [uv](https://docs.astral.sh/uv/)
(>= 0.4.27, required for `[dependency-groups]`). `pyproject.toml` is the source of
truth; `requirements.txt` was removed and must not be reintroduced.

On Debian or Ubuntu, install native build prerequisites first (`psycopg2` and uWSGI are
built from source):

```bash
sudo apt-get update
sudo apt-get install -y build-essential libpq-dev
```

Then sync:

```bash
uv sync
```

## Common commands

```bash
uv sync --locked          # install exactly the locked dependencies
uv run pytest             # run the test suite
uv run python manage.py init_db   # create database tables
uv run python run.py      # start the development server (http://localhost:5000)
docker-compose up -d --build      # run the full stack (db + app + https-portal)
```

## Testing

- Run with `uv run pytest`.
- Tests live in `tests/` and use `unittest.TestCase` classes executed by pytest.
- `pyproject.toml` sets `testpaths = ["tests"]` and `pythonpath = ["."]`.
- Tests patch `flask.config.Config.from_object` before importing the app so the suite
  runs against an in-memory SQLite database instead of PostgreSQL. Follow this pattern
  when importing `keywoo`.
- Do not name module-level helpers `test_*`: pytest will collect them as tests and fail
  (see `apply_test_config` in the test modules).

## Code style

- Python 3.11+ (see `requires-python` in `pyproject.toml`).
- Dependencies are pinned exactly in `pyproject.toml`; keep `uv.lock` in sync
  (`uv lock`).
- User-facing flash messages are written in Japanese; keep new ones consistent.
- `keywoo/passwords.py` keeps a legacy `sha256$` verification path for hashes created
  before the PBKDF2 upgrade. Accounts are transparently rehashed on next login; do not
  remove the legacy path without a migration plan.

## CI / workflows

- `test.yml` — `uv sync --locked` then `uv run pytest` on pushes to `main` and on PRs.
- `hadolint.yml` — lints the `Dockerfile` (config in `.hadolint.yaml`).
- `codeql-analysis.yml` — CodeQL for Python and JavaScript, config in
  `.github/codeql/codeql-config.yml`.
- `verify-actions-lock.yml` — verifies `.github/workflows/actions.lock`.
- `deploy-site.yml` — rsyncs to the server and restarts Compose on pushes to `main`.
- `bump-version.yml` — tags and creates a release on pushes to `main`.

### Workflow action pinning

`.github/workflows/actions.lock` pins workflow action dependencies and is generated by
the `gh-actions-lock` CLI extension. Do not edit it by hand. See
`.github/ACTIONS_LOCK.md` for the full workflow; after changing a `uses:` reference:

```bash
gh extension install github/gh-actions-lock --pin v0.4.1
gh actions-lock --no-narrow
gh actions-lock --verify
```

## Dependency updates

Renovate opens dependency PRs against `pyproject.toml` (`renovate.json`, automerge
enabled). When a dependency PR targets a file that no longer exists on `main`
(for example the old `requirements.txt`) or pins a version older than `main`, close it
as superseded rather than rebasing.
